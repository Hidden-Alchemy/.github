# Support

Hidden Alchemy uses a separation of channels so that **actionable engineering
work** stays visible in issues and **open-ended questions** live in
discussions.

## Where to ask

| You want to... | Channel |
|:---|:---|
| Ask a question that is not a bug or feature request | GitHub **Discussions → Help** category |
| Discuss an idea before formalizing it | GitHub **Discussions → Ideas** category |
| Report something that is broken | **Bug Report** issue form in the affected repository |
| Request a new capability | **Feature Request** issue form in the affected repository |
| Propose a new project or idea to the lab | **Idea Submission** issue form in the `ideas` repository |

> **Note:** The `ideas` repository and Discussions categories are introduced
> as part of the organization's infrastructure rollout (milestones M5–M7).
> Until Discussions are enabled, open-ended questions may be raised as GitHub
> Discussions on the organization profile; bugs and feature requests should
> always use the issue forms.

## What is *not* support

- Security vulnerabilities — report privately via **Security → Report a
  vulnerability** on the affected repository (see `SECURITY.md`). Never post
  vulnerability details in a public issue.
- Repository administration and membership — see `GOVERNANCE.md` for how
  membership works. Do not use issues to request org membership; use the
  **Membership Interest** form described there once it is live.

## Response expectations

Hidden Alchemy is maintained by a small Core Team on a best-effort basis.
Issues and discussions are triaged regularly, but there is no guaranteed
response-time SLA. If a `good first issue` or `help wanted` item is what you
need, look for issues carrying those labels.
